Parameter Optimization Strategy

This description applies to parameter optimization for an entire method.  For individual phenomena such as intermolecular interactions only one or two steps need be used.

An overview of parameter optimization describes the general procedure for parameterizing a method.  In this section details of the individual steps involved will be described. 

Basic Requirements

Any new method has three essential requirements: there must be a theoretical framework, a set of reference data, and a means to optimize the adjustable parameters to minimize the root-mean-square difference between the predicted values of properties and the reference values. Of these three, the parameter optimizer is highly reliable.  The theoretical framework is "quite good" - in recent years the fastest changes have occurred in the modeling of non-covalent interactions, such as dispersion and hydrogen bonding.  By far the least accurate of the requirements is the reference data set.  But with the development of highly accurate very high level theoretical methods it is likely that large amounts of new and accurate reference data will soon be available.

Theoretical framework

Before starting parameter optimization, the theoretical framework should exist and all adjustable parameters should be accessible to PARAM.  If a change is made to the theoretical framework then that change should be made to MOPAC only; the change is automatically made to PARAM when PARAM is re-compiled. Global parameters should be regarded as temporary, although some, such as the hydrogen bond parameters and the dispersion parameters, have a lifespan of many years.  Use different global parameters for different approximations!   

Reference data

Currently there is a large amount of reference data.  For convenience, these data are split into sets: "Data normal" as the name suggests this set consists of normal compounds. "Data levels" contains atomic and molecular ground and excited electronic states. "Data intermolecular interactions" This is further split into individual sets, such as S22 and X40, etc. These sets contain the energies of intermolecular interactions. Finally "Data erratic" contains various exotic systems for assisting in parameterization.  One group in this set has the generic name "core-core_AA - BB far" and "core-core_AA - BB near" where "AA" and "BB" are chemical symbols.  These systems are used in defining heats of formation and interatomic distances in solids. All these data-sets are estimates based on the properties of solds. 

Starting optimization

All method developments have a similar starting step where parameters for core elements H, C, N, O, F, S, P, Cl, Br, and I are optimized. Like all optimizations, this operation is performed by running PARAM with a data set. Data-sets should have informative names.  Without exception, every data set used in method development will need to be run more than once, some will need to be run many times as more information becomes available. A useful name for the very first data-set would be CHNOXSP.dat, and, as its name suggests, this data-set should include reference data for compounds that contain those elements only.  All parameters for the ten elements should be included, via the option "(H C N O F P S Cl Br I)(ALL)" for the choice of parameters to be optimized. The optimization should also include all global parameters that are set.

Make the data-set easy to read. Use comment lines to clearly describe what's being done. Use continuation lines where they will help make the data set look neat.

The first optimization run should include keyword CYCLES=1.  If no method is specified, PM8 will be used, which,  at this point, is essentially the same as PM6-D3H4. The only other method that might be worth looking at is PM7.  When this job is run it will stop after one cycle.  Carefully examine the output. Look at the lines after the line that contains "Time Heat Dipole I.P. Geometry Total" for unusually large contributions to the total error function, these contributions are most easily seen in the last number on each line.  If anything looks very wrong, in particular if the line ends with a string of asterisks, "***********", indicating a very large number, examine that system to find out what's gone wrong.  Also look for warning messages, these are lines that don't contain the name of a chemical system.  Take the appropriate action: either delete the entry or edit it so that the warning goes away.

Look at the updated parameters, these are in the lines after the line containing "Parameter Element New value Change Limits: Low High Penalty Gradient"  If any penalties are large, in the hundreds or thousands, consider changing the lower or upper limits for that parameter.

Finally, look for anything else that looks unexpected.  Once everything is satisfactory, remove the keyword CYCLES=1 from the data set and re-run.

Optimization of the parameters

Optimization of the parameters of a data-set like CHNOXSP.dat can take several days.  While the job is running, it is useful to monitor its progress using utility "watch.cmd"  Watch's default mode, "watch CHNOXSP",  is to display the tail of the output file, CHNOXSP.out.  When the output looks normal, set "watch" to monitor the error function by running "watch CHNOXSPSTART" This will monitor the total error function, this is equal to the contribution from the reference data files (the last number on the line that contains "TOTALS") plus any penalty arising from parameters that are outside their bounds. Another useful quantity to watch is unsigned average error; to do this use "watch CHNOXSP UNSIGN"

 When the optimization looks as if it's complete, kill the job.  The optimized parameters are then in file "CHNOXSP.rp" Run a survey to compare the accuracies of the new method with those of PM7 and PM6-D3H4.  The objective here is to establish that the current optimization has not caused a deterioration in the core elements. If a deterioration has occurred, find what went wrong and correct it.  Do not proceed until CHNOXSPis at least as good as that for PM7 or PM6-D3H4.

Extension to more Elements

Each of the remaining elements could be parameterized on its own.  Sets of reference data for several of the elements can be found in the folder "%PARAM_Start%/Parameter Optimization/Sets" Other sets can be constructed using files in the sub-folder Storeroom; these files were used in developing PM7.  To parameterize an element, for example aluminum, construct a PARAM data-set, e.g., Aluminum.dat.

Define the reference data set to be used, here "../sets/Aluminum.txt", the source of reference data, and the current CHNOXSP parameters, "../CHNOXSP/CHNOXSP.rp". In principle, each element can be optimized on its own.  An alternative would be to optimize parameters for sets of elements.  If there is a large amount of data on any particular element, it should be optimized on its own. Otherwise, the element could be bundled with other elements, for example "Group IA.dat", "Group IIA.dat" and "Group IIA.dat"  If important reference data involve two or more non-core elements, then these elements should be optimized together, e.g. "Mg and P.dat"

Transition metals, lanthanides, and solids

A large number of elements have special characteristics.  Some are known for their open-shell behavior, in particular electronic excited states. Each of these systems has to be defined as a reference data set.  Some have few reference data, e.g., silver, where few gas-phase data are available. Still other individual species are stubbornly uncooperative, such as the Fe4S4 clusters, these can either be the subject of a research effort to make them work, or they can be regarded as incorrigible, and simply labeled as such in release notes.

Parameterizing solids

Parameterizing solids presents a unique problem.  Of their nature, data-sets for solids are too large to use as reference data.  Also, there are many solids that involve interactions for which there are no simple chemical equivalents.  An example is the three polymorphs of Al2SiO5: kyanite, andalusite and sillimanite all of which have Si in proximity to Al.  Without appropriate reference data, the Si - Al diatomic interaction terms XFAC and ALPB cannot be parameterized.

A general method to parameterize the diatomic interactions is to use a special type of reference data in which each two-atom interaction is represented by precisely two atoms whose positions are not allowed to change.  In one reference data file the interatomic separation is artificially large, in another file the separation is artificially small. Two reference data are needed in order to define the values of both XFAC and ALPB, for this purpose two heats of formation are necessary.  These heats of formation are chosen so as to allow the geometry of the unit cell and the heat of formation of the solid to be reproduced with good accuracy.  This involves an iterative procedure:

The current values of the heats of formation of the near and far diatomic interaction are calculated.
The geometries of appropriate solids is calculated.
The heats of formation of the near and far diatomic interaction are modified to improve the calculated heat of formation of the solid and improve the relative positions of the two atoms in the solid.
This sequence is repeated as necessary.

"Annealing" parameters

After all elements have been parameterized, i.e., when the parameters from each optimization are the best they can be, an additional small improvement can be obtained by re-optimizing the core elements together with certain other elements.  Only well-behaved other elements should be considered for this operation, that is, only elements whose errors are similar to those in the core set should be considered.  In such an optimization the errors for the original core elements must increase, and the errors for systems involving non-core elements must decrease.
