Relationship of the Programs MOPAC2016 and PARAM

Program MOPAC2016 and program PARAM allow new methods to be parameterized and tested. MOPAC is a stand-alone program, and PARAM uses almost all of MOPAC as an embedded compute engine.  Both MOPAC and PARAM use the same set of source code.  This has the advantage that when a change is made in the source code of one program, that change will automatically be made in the other program.  MOPAC does not use any of the PARAM source code but PARAM uses almost all of the MOPAC source code, so any change made to the MOPAC source code will affect PARAM, but any change to PARAM source code will not affect MOPAC.  It might help to regard MOPAC as a compute engine embedded within PARAM.  In principle, many parts of MOPAC could be deleted, for example the MOZYME function is not used in PARAM and therefore could be deleted.  However by not modifying the copy of MOPAC used in PARAM, one potential path for introducing complications is eliminated.

Individual manuals on MOPAC and PARAM give detailed information on how each of these programs work.

Adding a new method to MOPAC

For convenience, all the changes needed for adding a new method to MOPAC have already been made.  Each method needs a name, and as the obvious next name in the PMx series in PM8, that name has been chosen for the new method.  This name, PM8, should not be regarded as fixed.  If a different name is preferred, editing the MOPAC files that refer to PM8 to change it to the preferred name is straightforward.

Both MOPAC and PARAM have their own Visual Studio solutions that allow development, running, and debugging of the programs.  There are also Makefiles for Windows, Mac and Linux.  Unlike the Visual Studio solutions, where MOPAC and PARAM files are in separate folders, the Makefiles use only one common set of source files.  This set can be constructed by copying all the files for MOPAC and PARAM into a new folder.  The Makefiles allow MOPAC and PARAM to be compiled for different platforms.  All small jobs should be run on the Windows platform, with larger jobs being run on other platforms, as needed.

Quite large parameter files are generated during method development.  Eventually these files become irritating in that they can significantly increase the size of PARAM and MOPAC output files.  These files can be eliminated by running a PARAM with a  data set that contains one line with the text " DEP EXTERNAL=<text>" or MOPAC job with a data-set consisting of four lines.  The first line should be the text: "PM8 DEP DEBUG EXTERNAL=<text>", lines 2 and 3 can be blank, and line 4 should contain a chemical symbol, e.g., " H " For both MOPAC and PARAM, keyword "EXTERNAL=<text>" indicates the name and location of the file that holds the new parameters.

Output from that job will include a file with the name "parameters_for_PM8_C.F90" that contains all the parameters for the method with old parameters being replaced with those in the "EXTERNAL" file. The file "parameters_for_PM8_C.F90" can then be moved or copied to the folder that holds the MOPAC source files.  When MOPAC or PARAM are recompiled, the updated parameters for PM8 will be used.  This operation is easy to do and takes only a minute or two.

Compiling MOPAC and PARAM on other platforms

Utility files for compiling MOPAC and PARAM on Mac and Linux systems are provided.  To reduce the frequency of errors caused by using multiple copies of files, the top copies of all files should be on the Windows platform.
